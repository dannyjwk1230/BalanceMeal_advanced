# BalanceMeal 구현 과정 및 프롬프트 목록

- 작성자: 정연호
- 프로젝트: Android 식단 기록 앱 BalanceMeal
- 개발 환경: Android Studio, Kotlin, Jetpack Compose
- 주요 구조: ViewModel, StateFlow, UDF, Navigation, 공통 Repository

## 프로젝트 개요

BalanceMeal은 음식과 섭취량을 기록하고 탄수화물·단백질·지방 및 칼로리를 확인하는 앱이다. 신체 정보를 설정하면 하루 권장 섭취량과 현재 섭취 상태를 비교할 수 있다.

개발은 UI 설계와 음식 데이터 준비를 시작으로 공통 모델·저장소·Navigation을 구성하고, 마이·기록·홈의 기능을 차례로 연결하는 순서로 진행하도록 요청하였다. 각 항목에는 프롬프트의 구현 의도와 단계 사이의 연결 관계를 설명하였다.

## 1. UI와 브랜드 설계

Google Stitch를 활용하여 공통 디자인 시스템과 화면·상태·적응형 배치를 설계하도록 요청하였다. 로고는 Gemini Image에 브랜드 의미와 색상·형태를 구체적으로 제시하였다.

### UI-01. 앱 목적·디자인 시스템·공통 화면 틀 정의

**구현 의도:** 식단 기록 앱의 목적과 다섯 화면이 공유할 시각적 기준을 먼저 정의한다.

**프롬프트**

```text
Android 식단 기록 앱 ‘BalanceMeal’의 UI를 단계적으로 디자인하려고 해.

사용자는 자신의 식단을 기록하고 탄수화물·단백질·지방의 구성과 섭취 칼로리를 확인한다. 신체 정보를 설정하면 하루 권장 섭취량도 확인할 수 있다. 모든 화면은 한국어로 구성해줘.

먼저 다음 기준으로 디자인 시스템과 공통 화면 프레임을 만들어줘.

카드형 섹션과 글래스모피즘 적용.

밝은 오프화이트 배경에 은은한 민트·라벤더 그라데이션 사용.

카드는 반투명한 흰색, 부드러운 배경 흐림, 얇은 밝은 테두리와 그림자로 표현.

카드의 둥근 모서리는 약 20~24px.

본문과 수치는 짙은 색으로 표시해 가독성 확보.

주요 버튼은 민트 계열로 강조.

한국어 글꼴과 둥근 선형 아이콘 사용.

탄수화물은 민트, 단백질은 라벤더, 지방은 부드러운 오렌지로 통일.

공통 상단바:
왼쪽에 로고와 BalanceMeal, 오른쪽에 원형 프로필 표시.
프로필을 누르면 마이페이지로 이동한다.

하단 내비게이션:
홈 / 기록 / 목록 / 분석 / 마이 순서.
선택된 항목을 명확하게 강조한다.

우선 색상·글꼴·카드·버튼·입력창·상단바·내비게이션의 공통 스타일을 정리해줘.
```

**과정 설명:** 공통 색상·카드·입력창·상단바·내비게이션을 먼저 정의하여 화면마다 일관된 디자인을 적용하도록 한다.

### UI-02. 홈의 영양 차트·칼로리·코멘트 설계

**구현 의도:** 홈에서 사용자가 오늘의 섭취 상태를 읽는 순서와 차트 표현을 설계한다.

**프롬프트**

```text
앞에서 만든 디자인 시스템을 적용해 홈 화면을 만들어줘.

위에서 아래 순서:

오늘 날짜와 ‘오늘의 영양 밸런스’ 제목

영양소 원형 차트 카드

차트 아래 오늘의 섭취 칼로리

식단 추가하기 버튼

기본 멘트와 서브 멘트로 구성된 코멘트 카드

원형 차트는 탄수화물·단백질·지방의 중량 합계를 100%로 표현한다.
영양소별 이름, 섭취량 g, 비율 %를 함께 표시해줘.

디자인 예시:

탄수화물 180g, 60.0%

단백질 70g, 23.3%

지방 50g, 16.7%

섭취 칼로리 1,450 kcal

한 끼만 기록했어도 현재까지의 실제 차트와 칼로리를 표시한다.
조식·중식·석식 중 빠진 기록이 있으면 식단 추가 버튼을 제공한다.

코멘트 예시:
‘오늘의 칼로리가 목표보다 부족해요.’
‘내일은 탄수화물 섭취에 신경 써보세요.’

차트, 핵심 수치, 코멘트의 시각적 위계가 분명하도록 구성해줘.
```

**과정 설명:** 차트·섭취 수치·식단 추가·코멘트의 정보 위계를 정한다. 초기 홈은 원형 차트로 설계하고, 이후 권장 범위를 비교하기 위한 막대그래프 방식으로 개선한다.

### UI-03. 기록 화면의 입력 영역과 저장 버튼 상태 설계

**구현 의도:** 날짜·시간·끼니·사진·음식·합계를 입력하는 화면과 신규/편집/삭제 상태를 설계한다.

**프롬프트**

```text
기존 스타일을 유지하면서 기록 화면을 추가해줘. 하단 내비게이션에서는 기록을 선택 상태로 표시해줘.

다음 순서로 카드형 섹션을 배치해줘.

날짜와 식사 시간 선택

신규 기록의 시간은 ‘식사 시간 선택’이라는 미입력 상태.

미래 날짜·시간에 대한 오류를 표시할 공간 확보.

식사 종류 선택

조식 / 중식 / 석식 / 간식·음료.

선택 상태가 명확한 칩 또는 세그먼트 사용.

사진

식단당 사진 최대 1장.

갤러리 선택과 카메라 촬영 버튼.

사진이 없으면 음식 아이콘이 있는 대체 영역.

음식 목록

음식 추가 버튼.

음식별 이름, 섭취량, g 또는 ml 단위, 수정·삭제 조작.

같은 음식도 별도 항목으로 표시할 수 있는 구조.

영양 합계

추가한 모든 음식의 탄수화물·단백질·지방 g과 kcal.

합계 아래 영양 정보 출처 표시.

저장 버튼

신규 작성은 ‘저장’.

기존 기록 편집은 ‘변경’.

기존 기록에서 음식이 모두 제거되면 ‘삭제’.

신규 작성에서 음식이 없으면 사진이 있어도 저장 비활성화.

스크롤과 하단 내비게이션을 고려해 마지막 버튼까지 편하게 접근하도록 디자인해줘.
```

**과정 설명:** 신규 기록, 기존 기록 편집, 마지막 음식 제거 상태를 구분하여 입력 영역과 저장·변경·삭제 버튼의 동작 기준을 정한다.

### UI-04. 음식 검색·선택·섭취량 입력 흐름 설계

**구현 의도:** 음식 추가 버튼 이후의 검색 목록과 섭취량 입력 과정을 구체화한다.

**프롬프트**

```text
기록 화면의 ‘음식 추가’에서 연결되는 음식 선택 화면과 섭취량 입력 바텀시트를 만들어줘.

음식 선택 화면:

음식 이름 검색창.

확정된 100개 음식에서 선택하는 목록.

음식 이름과 기준량 100g 또는 100ml 표시.

기준량당 탄수화물·단백질·지방 g과 kcal 표시.

각 음식을 선택할 수 있는 명확한 행 구조.

섭취량 입력 바텀시트:

선택한 음식 이름.

숫자 입력창과 해당 음식의 g 또는 ml 단위.

입력한 섭취량에 대한 영양 정보 미리보기.

취소와 추가 버튼.

음식을 추가한 뒤 기록 화면의 음식 목록과 영양 합계가 어떻게 보이는지도 디자인해줘.
목업에 사용하는 음식 이름과 수치는 디자인용 예시로 취급해줘.
```

**과정 설명:** 음식 검색과 선택, 섭취량 입력, 영양 정보 미리보기, 기록 화면 복귀가 하나의 흐름으로 이어지도록 한다. g과 ml는 음식의 기준 단위에 맞게 표시한다.

### UI-05. 목록·기간 선택·식단 상세 화면 설계

**구현 의도:** 기간별 기록 탐색과 날짜 카드에서 식단 상세로 이어지는 화면 구조를 설계한다.

**프롬프트**

```text
기존 디자인을 유지하면서 목록 화면과 연결되는 식단 상세 화면을 추가해줘.

목록 상단:

일 / 주 / 월 선택바.

선택된 시작일과 종료일.

달력 아이콘을 통한 기간 선택.

일은 1일, 주는 7일, 월은 30일.

최초 범위는 오늘을 포함한 최근 기간이며, 다른 기간을 선택해도 해당 일수는 고정.

날짜별 카드:

오래된 날짜가 위, 최근 날짜가 아래.

기록이 없는 날짜도 표시.

날짜, 하루 총열량, 기록한 끼니 수 표시.

기록된 조식·중식·석식·간식·음료 라벨 표시.

끼니 라벨을 누르면 작은 사진과 식사 시간이 있는 요약을 펼침.

펼쳐진 요약을 선택하면 상세 화면으로 이동.

사진이 없으면 음식 아이콘 사용.

미기록 날짜는 0 kcal, 0끼와 간결한 안내 표시.

식단 상세:

뒤로 가기.

큰 사진 또는 음식 아이콘 대체 영역.

날짜, 시간, 식사 종류.

음식별 이름, 섭취량과 단위, 해당 섭취량 기준 영양소와 kcal.

전체 영양소와 칼로리 합계.

목록과 상세 사이의 정보 연결이 자연스럽게 느껴지도록 구성해줘.
```

**과정 설명:** 기간 선택에서 날짜별 기록과 끼니 요약, 식단 상세로 이어지는 탐색 구조를 설계한다. 기록이 없는 날짜도 목록에서 확인할 수 있게 한다.

### UI-06. 분석의 평균·기간 합계·끼니별 카드 설계

**구현 의도:** 평균 섭취와 기간 총량을 혼동하지 않도록 분석 화면을 설계한다.

**프롬프트**

```text
분석 화면을 추가해줘. 홈과 동일한 원형 차트와 영양소 색상을 사용해줘.

위에서 아래 순서:

일 / 주 / 월 선택바와 달력·기간 표시

하루 평균 영양소 차트

하루 평균 칼로리

코멘트 카드

기간 총열량 카드

식사 종류별 영양소 분석

현재 신체 정보 기준 안내

기본 기간은 오늘을 포함한 최근 1일 / 7일 / 30일이다.
사용자 지정 범위를 고르는 달력 UI를 제공하되, 사용자 지정 기간의 길이 제한 정책은 새로 정하지 말아줘.

평균은 식단을 하나라도 기록한 날짜만 포함한다.
차트 비율은 기간 내 영양소 섭취량을 합산한 뒤 중량 기준으로 계산한다.

일관된 예시:
‘7일 중 4일 기록 기준 하루 평균’
하루 평균 1,450 kcal
기간 총열량 5,800 kcal

식사 종류별 분석:
조식·중식·석식·간식·음료 각각의 기간 합계 탄수화물·단백질·지방 g과 kcal를 표시한다.

하단 안내:
‘현재 저장된 신체 정보를 기준으로 평가합니다. 신체 정보가 변경되면 목표 섭취량과 분석 코멘트가 달라질 수 있습니다.’

하루 평균과 기간 합계가 명확하게 구분되도록 디자인해줘.
```

**과정 설명:** 하루 평균과 기간 총량을 구분하고, 기록한 날짜만 평균 분모에 포함하는 기준을 화면에 드러낸다.

### UI-07. 마이의 프로필·신체 정보·권장량 표시 설계

**구현 의도:** 프로필 수정과 신체 정보 입력, 권장량 표시를 하나의 화면 흐름으로 구성한다.

**프롬프트**

```text
마이페이지를 추가해줘. 하단 ‘마이’ 탭과 상단 프로필은 이 화면으로 연결해줘.

화면 순서:

원형 프로필과 닉네임 카드

신체 정보 설정 카드

저장 버튼

하루 권장 섭취량 카드

참고 안내와 출처

프로필:

기본 닉네임 First Account.

닉네임 수정과 프로필 사진 변경 조작 제공.

신체 정보:
생년월일 / 성별 / 키 cm / 체중 kg / 활동 수준.

  - fatG: 지방(g)

  - energyKcal: 에너지(kcal)

영양소는 원본의 100g 또는 100ml당 수치를 그대로 사용해줘. 식품중량을 영양소 기준량으로 사용하지 마. 결측값을 0으로 채우지 말고, 필수값이 없거나 음수·비정상 숫자인 행은 제외해줘. 원본의 실제 0은 유지하고 식품코드는 중복되지 않게 해줘.
```

**과정 설명:** 식품 코드·이름·단위와 기준량별 탄단지·칼로리로 데이터 계약을 제한한다. 실제 0과 결측값을 구분하여 잘못된 영양 수치가 들어가지 않게 한다.

**구현 의도:** 준비된 JSON을 앱에서 읽고 검색하며 g/ml별 영양 계산에 사용한다.

### DEV-13. 신체 정보 검증·성인 제한·편집 초안 분리

**구현 의도:** 유효한 다섯 항목만 한 번에 저장하고 미완성 입력이 기존 목표를 덮어쓰지 않게 한다.

### DEV-14. EER·활동계수·영양소 권장 범위 계산과 검증

**구현 의도:** 신체 정보로 에너지 추정량과 탄단지 권장 범위를 계산해 화면에 표시한다.

7. 빠른 날짜·끼니 전환 요청이 잘못된 기존 기록을 표시하지 않는지 확인한다.

[완료 조건]

**과정 설명:** 신규/기존과 음식 유무에 따라 저장·변경·삭제 버튼을 구분한다. 초안 편집과 실제 저장 연결을 단계적으로 나누고, 초안 변경이 저장소에 영향을 주지 않는지 확인하도록 한다.

  시스템 Back에서 동일한 정책을 적용해줘.

  날짜·끼니도 확인 전에 실제 선택을 바꾸지 마.

```

**과정 설명:** 날짜·끼니·탭·프로필·Back에 같은 미저장 확인 정책을 적용한다. 계속 작성은 초안을 유지하고 이동하기는 초안 변경만 버리며 저장된 식단은 보존하도록 한다.

4. 개발 가이드:

   - 백엔드 API 연동이나 기존 데이터 구조를 재설계하지 말고, 프론트엔드 렌더링 시점의 조건부 분기(Logical AND / Ternary operator) 방식으로만 가볍게 구현해줘.
```

**과정 설명:** 신체 정보 자체를 보존하면서 목표 계산 적용 여부를 토글로 제어한다. ON에서는 권장 범위·배지를 표시하고 OFF에서는 현재 섭취 수치 중심의 막대를 표시하도록 한다.
